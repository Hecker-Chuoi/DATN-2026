Vì sao tách 2 compose project?

  • Jenkins không được tự deploy lại chính nó. Nếu Jenkins nằm trong compose ứng dụng, lệnh docker compose up do Jenkins chạy có thể tự tắt Jenkins giữa chừng.
  • Caddy phải luôn sống, kể cả khi stack ứng dụng đang deploy hoặc đang lỗi. Có Caddy thì vẫn vào được Jenkins để sửa.
  • Hai project nói chuyện với nhau qua network ngoài datn-net, tạo sẵn bằng docker network create. Caddy gọi frontend:80, api-gateway:8081; Jenkins gọi api-gateway:8081 khi smoke test.

03Từ git push đến lúc lên server

  1. Merge vào main

    GitHub gửi POST tới https://jenkins.datn.example.com/github-webhook/. Request đi qua Caddy vào container jenkins.

  2. Jenkins nhận diện nhánh

    Multibranch Pipeline thấy commit mới trên main và chạy Jenkinsfile của chính commit đó. Pipeline được quản lý phiên bản cùng code.

  3. Checkout + so sánh

    Jenkins clone code vào /var/jenkins_home/workspace/… và chạy git diff giữa commit này với commit của lần build thành công gần nhất để biết service nào thay đổi.

  4. CI ngay trong container Jenkins

    mvn package (JDK 21 có sẵn) và npm ci/lint/build (Node 22). Thư viện cache trong ~/.m2 và ~/.npm thuộc volume jenkins_home, lần sau không phải tải lại.

  5. docker build qua docker.sock

    Docker CLI trong Jenkins gửi lệnh tới Docker Engine của EC2. Image được lưu luôn trong kho image của EC2, nên không cần registry: build ở đâu thì chạy ở đó.

  6. Sửa bảng tag và compose up -d

    Compose so sánh cấu hình mới với các container đang chạy và chỉ tạo lại container có tag đổi. DB, Keycloak và các service khác không bị động tới.

  7. Smoke test, ghi lịch sử, dọn dẹp

    Đợi mọi container healthy, gọi thử qua HTTPS như người dùng thật. Đạt thì lưu history/<số build>.env và xoá image cũ. GitHub hiện dấu ✓ cạnh commit.

056 quyết định thiết kế (và lý do)

5.1 Tag bất biến <số build>-<commit>, không dùng latest

Ví dụ datn/work-service:57-a1b2c3d: build #57, commit a1b2c3d. Nhìn tag là biết đang chạy code nào, mở được log build tương ứng. Tag latest bị ghi đè mỗi lần build nên không rollback được, và compose cũng không nhận ra có thay đổi.

5.2 Build once: Maven chạy một lần, image chỉ chép jar

Các Dockerfile hiện tại là multi-stage, mỗi Dockerfile tự chạy Maven bên trong. Build 5 service thì Maven chạy 5 lần, mỗi lần trong một container trắng và phải tải lại thư viện. Pipeline làm khác:

Cách cũ (5 Dockerfile multi-stage)

5 × (tải dependency + compile + package). Tốn RAM, chậm, và jar trong image không phải jar vừa được test.

Pipeline (Dockerfile.runtime)

mvn package một lần cho cả reactor (có cache ~/.m2). Mỗi image chỉ COPY *.jar vào JRE, mất khoảng 10 giây. Jar được test chính là jar được deploy.

Build context là backend/<svc>/target, trong đó chỉ có một file khớp *.jar (file *.jar.original do Spring Boot tạo không khớp glob). Image chạy bằng user thường, heap tự tính theo mem_limit (-XX:MaxRAMPercentage=70).

5.5 Jenkins điều khiển Docker của EC2 qua docker.sock, mount trùng đường dẫn

Jenkins chạy trong container nhưng không có Docker bên trong (không dùng "Docker-in-Docker"). Nó mount /var/run/docker.sock của EC2, nên mọi lệnh docker … trong Jenkins thực chất do Docker Engine của EC2 thực thi.

Hệ quả dễ vấp: đường dẫn được hiểu theo máy EC2 Trong compose có volumes: - /opt/datn/deploy/keycloak/realm.json:/opt/keycloak/…. Lệnh do Jenkins gửi, nhưng Docker Engine của EC2 mới là bên tìm file /opt/datn/deploy/keycloak/realm.json, và nó tìm trên ổ đĩa của EC2. Vì thế container Jenkins mount /opt/datn:/opt/datn (trùng đường dẫn hai phía): file Jenkins chép vào /opt/datn/deploy nằm đúng chỗ Docker Engine tìm. Nếu chạy compose từ workspace của Jenkins (/var/jenkins_home/…, nằm trong volume), Docker sẽ báo bind source path does not exist.
Bảo mật: docker.sock tương đương quyền root Ai chạy được lệnh trong Jenkins thì có quyền root trên EC2. Vì vậy: đặt mật khẩu admin mạnh, không cho tự đăng ký tài khoản, cho executors chạy trên built-in node (chấp nhận được với 1 server), và trong Multibranch đặt Discover pull requests from forks → Trust = "From users with Admin or Write permission", để PR từ fork lạ không chạy được Jenkinsfile đã bị sửa trên server.

5.6 Healthcheck & thứ tự khởi động

  • depends_on: condition: service_healthy: identity-service chỉ khởi động khi app-db và keycloak đã healthy, tránh lỗi "connection refused" lúc boot.
  • Bốn service chưa có actuator dùng nc -z 127.0.0.1 <port>. Spring Boot chỉ mở cổng HTTP ở cuối quá trình khởi động, nên "cổng đã mở" xấp xỉ "đã sẵn sàng". Gateway có actuator nên kiểm tra /actuator/health.
  • Ở Hướng 1, healthcheck không chặn traffic. Trong 20–60 giây service mới khởi động, gateway có thể trả 502/503 cho request tới service đó. Đây là khác biệt chính so với Hướng 2.
  • Mỗi container có mem_limit, nên một service rò rỉ bộ nhớ chỉ tự chết và tự khởi động lại, không kéo sập cả máy.

06Rollback: tự động và bằng tay

Tự động

Khi stage 6 hoặc 7 lỗi

Khối post { failure } chép history/before-N.env (chụp ngay trước khi sửa) đè lên deployed.env, rồi chạy lại compose up -d. Các service về đúng image cũ, khoảng 1 phút. Build vẫn đỏ để bạn biết có sự cố.

Bằng tay

Phát hiện lỗi sau vài giờ

Jenkins → job main → Build with Parameters → ROLLBACK_TO=42. Pipeline chép history/42.env thành deployed.env, deploy rồi smoke test. Chỉ chọn được build đã deploy thành công và image còn trên máy (giữ 5 lần gần nhất).

Sau khi rollback tay, lần build kế tiếp nên bật BUILD_ALL Build rollback cũng được tính là "thành công", nên mốc so sánh của lần sau là commit mới nhất trong khi image đang chạy là bản cũ. Nếu không bật BUILD_ALL, các service đã bị rollback sẽ không được build lại.
Giới hạn: rollback KHÔNG quay ngược database Flyway (work-service V1…V8, workspace-service V1…V4) và Hibernate ddl-auto: update chỉ tiến, không lùi. Rollback code về bản cũ chỉ an toàn khi migration mới tương thích ngược, theo nguyên tắc expand → contract:
  • Thêm bảng hoặc cột (nullable / có default): an toàn, code cũ bỏ qua cột mới.
  • Đổi tên hoặc xoá cột: chia thành 2 lần phát hành. Lần 1 thêm cột mới và ghi cả hai; lần 2, khi chắc chắn không cần quay lại nữa, mới xoá cột cũ.
  • Trước khi merge migration lớn vào main: chạy backup thủ công (mục 9).

// =============================================================================
// Jenkinsfile – HƯỚNG 1: Docker thuần trên 1 EC2
// Đặt trong repo tại: infrastructure/cicd/docker/Jenkinsfile
// Jenkins: Multibranch Pipeline → Build Configuration → Script Path = infrastructure/cicd/docker/Jenkinsfile
//
// Luồng:
//   1 Checkout → 2 Phát hiện thay đổi → 3 CI backend → 4 CI frontend
//   → (chỉ nhánh main) 5 Build image → 6 Deploy (docker compose) → 7 Smoke test
//   → lỗi ở 6/7 thì TỰ ĐỘNG ROLLBACK về trạng thái trước đó.
// Nhánh khác / Pull Request: chỉ chạy 1→4 (CI), không đụng tới server đang chạy.
//
// Credential cần tạo trong Jenkins:
//   - datn-prod-env : Secret file (nội dung theo docs/cicd/common/prod.env.example)
//   - Credential GitHub (PAT) gắn vào nguồn Multibranch nếu repo private
// =============================================================================
import groovy.transform.Field

@Field List<String> BACKEND_SERVICES = ['identity-service', 'api-gateway', 'work-service', 'workspace-service', 'notification-service']

// work-service -> WORK_SERVICE_TAG (tên biến trong deployed.env và docker-compose.prod.yml)
String tagKey(String svc) {
  return svc.toUpperCase().replace('-', '_') + '_TAG'
}

void addOnce(List<String> list, String item) {
  if (!list.contains(item)) { list.add(item) }
}

pipeline {
  agent any

  options {
    skipDefaultCheckout(true)
    timestamps()
    disableConcurrentBuilds()                       // 1 server → không cho 2 lần deploy chồng nhau
    buildDiscarder(logRotator(numToKeepStr: '30'))
    timeout(time: 45, unit: 'MINUTES')
  }

  parameters {
    booleanParam(name: 'BUILD_ALL', defaultValue: false,
      description: 'Bỏ qua phát hiện thay đổi: build + deploy TẤT CẢ service (dùng cho lần đầu hoặc sau rollback)')
    string(name: 'ROLLBACK_TO', defaultValue: '',
      description: 'Số build muốn quay về, ví dụ 42 (phải là build deploy thành công). Để trống = chạy bình thường')
  }

  environment {
    // ĐỔI cho khớp APP_DOMAIN / AUTH_DOMAIN trong prod.env
    APP_DOMAIN    = 'datn.example.com'
    AUTH_DOMAIN   = 'auth.datn.example.com'
    DEPLOY_BRANCH = 'main'
    CICD_DIR      = 'infrastructure/cicd/docker'
    DEPLOY_DIR    = '/opt/datn/deploy'
    STATE_DIR     = '/opt/datn/state'
    COMPOSE       = 'docker compose -p datn -f /opt/datn/deploy/docker-compose.prod.yml'
    MAVEN_OPTS    = '-Xmx1g'
  }

  stages {

    stage('1. Checkout') {
      steps {
        script {
          def scmVars = checkout scm
          env.PREV_OK_COMMIT   = scmVars.GIT_PREVIOUS_SUCCESSFUL_COMMIT ?: ''
          env.GIT_SHORT        = sh(returnStdout: true, script: 'git rev-parse --short=7 HEAD').trim()
          env.TAG              = "${env.BUILD_NUMBER}-${env.GIT_SHORT}"      // vd 57-a1b2c3d: truy ngược được build + commit
          env.IS_DEPLOY_BRANCH = (env.BRANCH_NAME == env.DEPLOY_BRANCH) ? 'true' : 'false'
          env.MODE             = params.ROLLBACK_TO?.trim() ? 'rollback' : 'build'

          if (env.MODE == 'rollback') {
            if (env.IS_DEPLOY_BRANCH != 'true') { error("Chỉ rollback trên nhánh ${env.DEPLOY_BRANCH}") }
            if (!params.ROLLBACK_TO.trim().matches(/\d+/)) { error('ROLLBACK_TO phải là số build') }
          }
          echo "Nhánh=${env.BRANCH_NAME} | TAG=${env.TAG} | Chế độ=${env.MODE} | Mốc so sánh=${env.PREV_OK_COMMIT ?: '(chưa có)'}"
        }
      }
    }

    stage('2. Phát hiện thay đổi') {
      when { environment name: 'MODE', value: 'build' }
      steps {
        script {
          List<String> files = null                       // null = không so sánh được → build tất cả
          if (!params.BUILD_ALL && env.PREV_OK_COMMIT) {
            int rc = sh(returnStatus: true, script: "git diff --name-only ${env.PREV_OK_COMMIT} HEAD > .changed-files")
            if (rc == 0) {
              files = []
              for (String line : readFile('.changed-files').split('\n')) {
                if (line.trim()) { files.add(line.trim()) }
              }
            }
          }

          List<String> selected = []
          boolean infra = false
          if (files == null) {
            selected.addAll(BACKEND_SERVICES)
            selected.add('frontend')
            infra = true
            echo 'Build đầu tiên / BUILD_ALL / không diff được → chọn TẤT CẢ service'
          } else {
            for (String f : files) {
              // Sửa thư viện dùng chung hoặc pom cha → mọi service backend bị ảnh hưởng
              if (f.startsWith('backend/common/') || f == 'backend/pom.xml' || f == 'backend/Dockerfile.runtime') {
                for (String s : BACKEND_SERVICES) { addOnce(selected, s) }
              }
              for (String s : BACKEND_SERVICES) {
                if (f.startsWith("backend/${s}/".toString())) { addOnce(selected, s) }
              }
              if (f.startsWith('frontend/')) { addOnce(selected, 'frontend') }
              if (f.startsWith("${env.CICD_DIR}/".toString()) || f.startsWith('infrastructure/keycloak/')) { infra = true }
            }
            echo "Có ${files.size()} file thay đổi:\n" + files.join('\n')
          }

          boolean backendChanged = false
          for (String s : selected) { if (s != 'frontend') { backendChanged = true } }

          env.SERVICES         = selected.join(' ')
          env.HAS_SERVICES     = selected ? 'true' : 'false'
          env.BACKEND_CHANGED  = backendChanged ? 'true' : 'false'
          env.FRONTEND_CHANGED = selected.contains('frontend') ? 'true' : 'false'
          env.INFRA_CHANGED    = infra ? 'true' : 'false'
          echo "Service cần build: [${env.SERVICES}] | Hạ tầng đổi: ${env.INFRA_CHANGED}"
          if (!selected && !infra) { echo 'Không có gì cần build/deploy (vd chỉ sửa docs) → các stage sau sẽ được bỏ qua' }
        }
      }
    }

    stage('3. CI · Backend: unit test + đóng gói jar') {
      when { allOf { environment name: 'MODE', value: 'build'; environment name: 'BACKEND_CHANGED', value: 'true' } }
      steps {
        dir('backend') {
          // Một lệnh cho cả reactor: common build trước, test của MỌI module đều chạy.
          // ~/.m2 nằm trong volume jenkins_home → lần sau không tải lại thư viện.
          sh 'mvn -B -ntp clean package'
        }
      }
      post {
        always { junit allowEmptyResults: true, testResults: 'backend/**/target/surefire-reports/*.xml' }
      }
    }

    stage('4. CI · Frontend: lint + build') {
      when { allOf { environment name: 'MODE', value: 'build'; environment name: 'FRONTEND_CHANGED', value: 'true' } }
      steps {
        dir('frontend') {
          sh 'npm ci --no-audit --no-fund'
          sh 'npm run lint'
          sh 'npm run build'
        }
      }
    }

    stage('5. Build Docker images') {
      when {
        allOf {
          environment name: 'MODE', value: 'build'
          environment name: 'IS_DEPLOY_BRANCH', value: 'true'
          environment name: 'HAS_SERVICES', value: 'true'
        }
      }
      steps {
        script {
          for (String s : env.SERVICES.split(' ')) {
            if (s == 'frontend') {
              // VITE_* bị "đóng băng" vào bundle lúc build → truyền URL Keycloak thật qua build-arg
              sh """
                docker build -t datn/frontend:${env.TAG} \\
                  --build-arg VITE_KEYCLOAK_URL=https://${env.AUTH_DOMAIN} \\
                  --build-arg NGINX_CONF=nginx.prod.conf \\
                  frontend
              """
            } else {
              // Jar đã có ở stage 3 → image chỉ chép jar (build once)
              sh "docker build -f backend/Dockerfile.runtime -t datn/${s}:${env.TAG} backend/${s}/target"
            }
          }
          sh "docker images --filter reference='datn/*:${env.TAG}'"
        }
      }
    }

    stage('6. Deploy (docker compose)') {
      when {
        allOf {
          environment name: 'IS_DEPLOY_BRANCH', value: 'true'
          anyOf {
            environment name: 'MODE', value: 'rollback'
            environment name: 'HAS_SERVICES', value: 'true'
            environment name: 'INFRA_CHANGED', value: 'true'
          }
        }
      }
      steps {
        withCredentials([file(credentialsId: 'datn-prod-env', variable: 'PROD_ENV')]) {
          // a) Đồng bộ file triển khai từ repo sang thư mục CỐ ĐỊNH trên host + chụp lại trạng thái cũ
          sh '''
            set -eu
            mkdir -p "$DEPLOY_DIR/keycloak" "$STATE_DIR/history"
            cp "$CICD_DIR/docker-compose.prod.yml" "$DEPLOY_DIR/docker-compose.prod.yml"
            cp infrastructure/keycloak/realm-export_08082026.json "$DEPLOY_DIR/keycloak/realm.json"
            touch "$STATE_DIR/deployed.env"
            cp "$STATE_DIR/deployed.env" "$STATE_DIR/history/before-$BUILD_NUMBER.env"
          '''
          // b) Cập nhật "bảng tag" deployed.env = trạng thái MONG MUỐN của hệ thống
          script {
            if (env.MODE == 'rollback') {
              sh """
                test -f ${env.STATE_DIR}/history/${params.ROLLBACK_TO}.env || { echo 'Không có history/${params.ROLLBACK_TO}.env'; exit 1; }
                cp ${env.STATE_DIR}/history/${params.ROLLBACK_TO}.env ${env.STATE_DIR}/deployed.env
              """
            } else if (env.HAS_SERVICES == 'true') {
              for (String s : env.SERVICES.split(' ')) {
                String key = tagKey(s)
                sh """
                  if grep -q '^${key}=' ${env.STATE_DIR}/deployed.env; then
                    sed -i 's/^${key}=.*/${key}=${env.TAG}/' ${env.STATE_DIR}/deployed.env
                  else
                    echo '${key}=${env.TAG}' >> ${env.STATE_DIR}/deployed.env
                  fi
                """
              }
            }
            env.DEPLOY_STARTED = 'true'
          }
          // c) Áp trạng thái: compose chỉ tạo lại container nào có cấu hình/tag thay đổi
          sh '''
            set -eu
            echo "----- deployed.env -----"; cat "$STATE_DIR/deployed.env"
            $COMPOSE --env-file "$PROD_ENV" --env-file "$STATE_DIR/deployed.env" up -d --remove-orphans
          '''
        }
      }
    }

    stage('7. Smoke test') {
      when { environment name: 'DEPLOY_STARTED', value: 'true' }
      steps {
        sh '''
          set -u
          echo "Chờ mọi container của project datn healthy (tối đa ~6 phút)..."
          BAD=""
          for i in $(seq 1 72); do
            BAD=$(docker ps --filter label=com.docker.compose.project=datn --format '{{.Names}}: {{.Status}}' \
                  | grep -E 'health: starting|unhealthy|Restarting' || true)
            [ -z "$BAD" ] && break
            sleep 5
          done
          if [ -n "$BAD" ]; then echo "Container chưa ổn định:"; echo "$BAD"; exit 1; fi
          docker ps --filter label=com.docker.compose.project=datn --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'

          set -e
          # Đi đúng đường người dùng đi: DNS → Caddy (HTTPS) → container
          curl -fsS --retry 5 --retry-delay 5 -o /dev/null "https://$APP_DOMAIN/"
          # Keycloak sống + realm đã import + issuer đúng URL công khai (sai là login hỏng toàn bộ)
          curl -fsS --retry 5 --retry-delay 5 "https://$AUTH_DOMAIN/realms/datn-realm/.well-known/openid-configuration" \
            | grep -q "\\"issuer\\":\\"https://$AUTH_DOMAIN/realms/datn-realm\\""
          # Gateway (Jenkins nằm chung network datn-net nên gọi được tên container)
          curl -fsS --retry 5 --retry-delay 5 http://api-gateway:8081/actuator/health | grep -q UP
          echo "SMOKE TEST OK"
        '''
        // Chỉ bản deploy QUA được smoke test mới được lưu vào lịch sử để rollback về sau
        sh 'cp "$STATE_DIR/deployed.env" "$STATE_DIR/history/$BUILD_NUMBER.env"'
      }
    }
  }

  post {
    failure {
      script {
        if (env.DEPLOY_STARTED == 'true') {
          echo 'Deploy hoặc smoke test lỗi → TỰ ĐỘNG ROLLBACK về trạng thái ngay trước build này'
          withCredentials([file(credentialsId: 'datn-prod-env', variable: 'PROD_ENV')]) {
            sh '''
              cp "$STATE_DIR/history/before-$BUILD_NUMBER.env" "$STATE_DIR/deployed.env"
              $COMPOSE --env-file "$PROD_ENV" --env-file "$STATE_DIR/deployed.env" up -d --remove-orphans \
                || echo "ROLLBACK cũng lỗi (vd lần deploy đầu tiên) → vào server kiểm tra bằng tay"
            '''
          }
        }
      }
      // Gửi mail (cần cấu hình SMTP trong Manage Jenkins → System → Extended E-mail):
      // emailext to: 'nhom@example.com', subject: "[DATN] FAILED ${env.JOB_NAME} #${env.BUILD_NUMBER}", body: "${env.BUILD_URL}"
    }
    success {
      script {
        if (env.DEPLOY_STARTED == 'true') {
          // Dọn image cũ: chỉ giữ các tag còn xuất hiện trong 5 lần deploy thành công gần nhất
          sh '''
            KEEP=$(ls -t "$STATE_DIR"/history/[0-9]*.env 2>/dev/null | head -5 | xargs -r cat | cut -d= -f2 | sort -u)
            docker images --format '{{.Repository}}:{{.Tag}}' | grep '^datn/' | grep -v '^datn/jenkins:' | while read -r img; do
              echo "$KEEP" | grep -qx "${img#*:}" || docker rmi "$img" >/dev/null 2>&1 || true
            done
            docker image prune -f >/dev/null
            docker builder prune -f --filter until=72h >/dev/null || true
            df -h / | tail -1
          '''
        }
      }
    }
    // "cleanup" luôn chạy SAU CÙNG (sau failure/success) → dọn workspace an toàn
    cleanup {
      cleanWs(deleteDirs: true, notFailBuild: true)
    }
  }
}

#!/usr/bin/env bash
# =============================================================================
# setup-ec2.sh – HƯỚNG 1: chuẩn bị EC2 Ubuntu 24.04 (chạy MỘT lần)
#   scp setup-ec2.sh ubuntu@<EIP>:~ && ssh ubuntu@<EIP> 'sudo bash setup-ec2.sh'
# =============================================================================
set -euo pipefail

echo "==> 1. Cài Docker Engine + Compose plugin (repo chính thức của Docker)"
apt-get update
apt-get install -y ca-certificates curl gnupg git
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
usermod -aG docker ubuntu   # user ubuntu chạy docker không cần sudo (đăng nhập lại để có hiệu lực)

echo "==> 2. Giới hạn log mặc định của Docker (tránh đầy ổ đĩa)"
cat > /etc/docker/daemon.json <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "20m", "max-file": "3" }
}
EOF
systemctl restart docker

echo "==> 3. Tạo swap 4GB (đệm khi Maven/npm/docker build ăn RAM đột biến)"
if ! swapon --show | grep -q /swapfile; then
  fallocate -l 4G /swapfile
  chmod 600 /swapfile
  mkswap /swapfile
  swapon /swapfile
  echo '/swapfile none swap sw 0 0' >> /etc/fstab
fi
echo 'vm.swappiness=10' > /etc/sysctl.d/99-datn.conf
sysctl --system >/dev/null

echo "==> 4. Thư mục làm việc"
#   platform : jenkins.Dockerfile, docker-compose.platform.yml, Caddyfile, .env (bạn copy vào)
#   deploy   : Jenkins chép docker-compose.prod.yml + realm.json vào mỗi lần deploy
#   state    : deployed.env (tag đang chạy) + history/ (để rollback)
#   backups  : file pg_dump hằng ngày
mkdir -p /opt/datn/{platform,deploy/keycloak,state/history,backups}
chown -R 1000:1000 /opt/datn/deploy /opt/datn/state   # uid 1000 = user jenkins trong container

echo "==> 5. Network dùng chung giữa compose platform (Jenkins, Caddy) và compose ứng dụng"
docker network inspect datn-net >/dev/null 2>&1 || docker network create datn-net

echo "==> 6. Tạo file .env cho docker-compose.platform.yml"
DOCKER_GID=$(getent group docker | cut -d: -f3)
if [ ! -f /opt/datn/platform/.env ]; then
  cat > /opt/datn/platform/.env <<EOF
DOCKER_GID=${DOCKER_GID}
ACME_EMAIL=ban@example.com
APP_DOMAIN=datn.example.com
AUTH_DOMAIN=auth.datn.example.com
JENKINS_DOMAIN=jenkins.datn.example.com
EOF
fi

echo
echo "XONG. Bước tiếp theo:"
echo "  1) Sửa /opt/datn/platform/.env (email + 3 tên miền)"
echo "  2) Copy jenkins.Dockerfile, docker-compose.platform.yml, Caddyfile vào /opt/datn/platform"
echo "  3) cd /opt/datn/platform && docker compose up -d --build"
echo "  4) Lấy mật khẩu mở khoá Jenkins: docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword"
