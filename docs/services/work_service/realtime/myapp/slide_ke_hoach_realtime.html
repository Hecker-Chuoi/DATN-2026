Vì sao STOMP?

Hai chiều (presence), nhiều kênh trên một kết nối, ChannelInterceptor kiểm quyền, có /user/queue để gửi riêng.

Vì sao AFTER_COMMIT?

Không bao giờ báo một thay đổi đã rollback. Realtime lỗi cũng không làm hỏng nghiệp vụ.

Vì sao không dùng Kafka cho UI?

UI luôn lấy lại dữ liệu từ DB nên không cần bền. Kafka thêm độ trễ của poller. Kafka để dành cho R3 (thông báo, automation).

Vì sao permitAll handshake?

Trình duyệt không đặt được header khi mở WebSocket. Token trên URL sẽ lộ vào log.

Không có SecurityContext

Trong luồng STOMP phải đọc quyền từ Principal. userId luôn là Keycloak sub.

Thu hồi quyền

Xoá thành viên thì gửi ACCESS_REVOKED và chủ động đóng session đó.

  "changes":  { "assigneeId": "minh" },

Dùng map nên phân biệt được "không gửi" với "đặt rỗng": {"assigneeId": null} = bỏ giao việc, sửa luôn lỗi hiện tại.

409 Conflict
{
  "code": "FIELD_CONFLICT",
  "conflicts": [{
    "field": "assigneeId",
    "expected": "nam", "actual": "lan",
    "changedBy": "<sub của A>",
    "changedAt": "2026-11-12T10:21:04"
  }],
  "item": { …bản mới nhất, "version": 6 }
}

changedBy và changedAt lấy từ work_item_changelogs (đã có). Kèm item để client vẽ lại mà không cần gọi thêm.

Tất cả hoặc không: một trường xung đột thì không lưu trường nào. force: true chỉ gửi khi người dùng bấm "Vẫn đổi".

Mỗi ô có 3 lớp: server · đang gửi · đang sửa

// Hiển thị: đang sửa → đang gửi → server
shown(f) = editing[f] ? draft[f]
         : f in pending ? pending[f]
         : server[f]

onRemoteEvent(e):
  if (e.originClientId == TAB_ID) return // tab mình
  if (e.version <= server.version) return // ⑤ cũ
  item = await fetchSilent()       // không spinner
  for f of e.changedFields:
    if (f in pending)        keep(f)          // ④
    else if (editing[f] || menuOpen[f])
                             hintAt(f, e.actor) // ③
    else { server[f] = item[f]; flash(f, e.actor) }
  server.version = item.version

Khi bấm chọn giá trị

pending[f] = mới, rồi gửi PATCH /fields kèm expected = server[f]. Thành công thì áp response nếu version lớn hơn. Bị 409 thì server = body.item và hiện hộp xung đột.

  • Thông báo in-app / automation
